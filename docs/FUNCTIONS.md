# 기능 변경 명세

## 1. 설정 화면

### 1-1. 데이터 저장 영역 변경

기존 `데이터 저장` 섹션을 삭제한다.

기존 데이터 저장 영역에 있던 기능 중 필요한 버튼을 화면 최하단으로 이동한다.

#### 버튼 배치

* `로그아웃` 버튼
* `저장 데이터 삭제` 버튼
* 두 버튼을 가로로 배치한다.
* 화면의 전체 너비를 사용하지 않고 **전체 영역의 약 1/3 너비**만 차지하도록 한다.
* 버튼 영역은 화면 **가장 하단 오른쪽**에 배치한다.
* 두 버튼이 포함된 하나의 작은 영역이 우측에 배치되는 형태로 구성한다.

---

### 1-2. 카테고리

#### 새 카테고리 이름 입력

기존 새 카테고리 이름을 입력하는 Input의 **border를 제거**한다.

#### 새 카테고리 색상 선택

카테고리를 생성할 때 색상을 선택할 수 있도록 변경한다.

* 기본으로 제공되는 **미리 정의된 색상 목록**을 제공한다.
* 사용자가 직접 원하는 색상을 선택할 수 있도록 **Color Picker**를 제공한다.
* 사용자는 기본 색상 또는 직접 선택한 색상 중 하나를 사용할 수 있다.
* 선택한 색상은 해당 카테고리의 색상으로 저장한다.

#### 카테고리별 미완료 할 일 표시

기존 카테고리 리스트 하단에 표시되는

> `할 일 5개에서 사용중`

형태의 문구를 제거한다.

대신 해당 카테고리에 연결된 **미완료 할 일의 개수**를 표시한다.

예시:

```text
3개 미완료 남음
```

표시되는 개수는 해당 카테고리에 연결된 할 일 중 **체크되지 않은 할 일의 개수**만 계산한다.

* 완료된 할 일 → 개수에서 제외
* 미완료 할 일 → 개수에 포함
* 미완료 할 일이 0개인 경우 → **미완료 관련 문구를 표시하지 않음**

# 2. 홈 화면

## 2-1. 전체 레이아웃 변경

기존 캘린더 영역과 Todo 영역을 구분하는 **명확한 경계를 제거**한다.

* 캘린더와 Todo 영역을 하나의 연결된 화면처럼 구성한다.
* 별도의 border 또는 영역 구분선으로 두 영역을 나누지 않는다.

### Todo 영역 위치

캘린더 바로 옆에 Todo 영역을 배치한다.

```text
┌───────────────────────┬──────────────────────┐
│                       │                      │
│       Calendar        │        Todo          │
│                       │                      │
│                       │                      │
└───────────────────────┴──────────────────────┘
```

단, 위 영역 사이에 **시각적인 경계선은 두지 않는다.**

## 2-2. 기존 좌측 메뉴바 제거

현재 홈 화면의 전체 왼쪽 영역에 존재하는 메뉴바를 제거한다.

대신 다음 두 버튼만 화면 상단에 고정한다.

* `설정`
* `프로필`

### 상단 버튼

* 화면 상단 영역에 배치한다.
* 스크롤 시에도 고정되어 있도록 한다.
* 기존 좌측 메뉴바가 차지하던 공간은 제거한다.
* 홈 화면의 캘린더 + Todo 영역이 좌측 메뉴바 제거 후 확보된 전체 공간을 사용할 수 있도록 한다.

## 2-3. 캘린더의 할 일 표시 방식 변경

기존에는 캘린더의 날짜에 해당하는 할 일을 텍스트 형태로 직접 표시한다.

이를 **카테고리 기반 요약 형태**로 변경한다.

### 기본 표시

각 날짜에 할 일이 존재하는 경우, 할 일의 제목을 표시하지 않는다.

대신 해당 날짜에 등록된 할 일의 **카테고리 색상과 미완료 개수**를 표시한다.

하나의 카테고리는 다음과 같은 형태로 표시한다.

```text
┌──────────────┐
│ 공부       3 │
└──────────────┘
```

* 카테고리 이름은 해당 카테고리의 색상을 background로 사용한다.
* 카테고리 이름을 하나의 블록 형태로 감싼다.
* 블록의 오른쪽에는 해당 카테고리의 **미완료 할 일 개수**를 표시한다.
* 완료된 할 일은 개수에 포함하지 않는다.
* 미완료 할 일이 없는 경우에는 **개수를 표시하지 않는다.**

### 카테고리 표시 예시

하나의 날짜에 여러 카테고리의 할 일이 있는 경우:

```text
┌──────────────┐
│ 업무       2 │
└──────────────┘

┌──────────────┐
│ 운동       1 │
└──────────────┘

┌──────────────┐
│ 공부       3 │
└──────────────┘
```

## 2-4. 완료된 카테고리 표시

해당 날짜의 특정 카테고리에 연결된 할 일이 **모두 완료된 경우**, 해당 카테고리 블록은 기존 색상보다 **조금 어둡게** 표시한다.

예:

```text
미완료

┌──────────────┐
│ 공부       2 │
└──────────────┘


전체 완료

┌──────────────┐
│ 공부         │
└──────────────┘
```

전체 완료 상태에서는 미완료 개수인 `0`을 표시하지 않는다.

완료 여부는 해당 카테고리에 연결된 할 일이 모두 완료되었는지를 기준으로 판단한다.

# 3. 데이터 처리 기준

## 카테고리별 미완료 개수

카테고리별 미완료 개수는 다음 조건으로 계산한다.

```text
카테고리에 연결된 전체 할 일
→ 완료되지 않은 할 일만 필터링
→ 필터링된 개수를 표시
```

미완료 할 일이 없는 경우에는 미완료 개수를 표시하지 않는다.

## 날짜별 카테고리 미완료 개수

캘린더에서는 특정 날짜에 등록된 할 일만 대상으로 계산한다.

```text
특정 날짜의 할 일
→ 카테고리별 그룹화
→ 완료되지 않은 할 일만 계산
→ 카테고리 색상 + 미완료 개수 표시
```

## 전체 완료 상태

특정 날짜의 특정 카테고리에 연결된 할 일이 모두 완료된 경우:

* 해당 카테고리 블록의 색상을 어둡게 처리한다.
* 미완료 개수는 표시하지 않는다.

# 1. 캘린더 월 자동 전환

## 요구사항

캘린더를 위아래로 스크롤할 때 현재 보고 있는 날짜에 따라 **자동으로 다음/이전 월로 전환**되도록 변경한다.

### 동작

* 캘린더를 위쪽으로 스크롤하면 이전 월로 이동한다.
* 캘린더를 아래쪽으로 스크롤하면 다음 월로 이동한다.
* 월이 변경될 때 현재 캘린더의 데이터도 해당 월 기준으로 갱신한다.
* 사용자가 자연스럽게 연속해서 월을 탐색할 수 있어야 한다.

### UX

사용자가 월을 선택하기 위해 별도의 버튼을 반복해서 누르지 않아도 되도록 한다.

```text
9월
  ↑ 스크롤
8월

10월
  ↓ 스크롤
11월
```

### 구현 시 주의사항

* 스크롤 중 월이 지나치게 빠르게 변경되지 않도록 한다.
* 동일한 스크롤 동작으로 월 변경 이벤트가 여러 번 발생하지 않도록 처리한다.
* 기존 날짜 선택 및 Todo 연동 기능은 유지한다.
* 기존 캘린더의 날짜별 카테고리 표시 기능을 유지한다.

# 2. 전체 화면 캘린더 / Todo 영역 비율 변경

현재 전체 화면에서 캘린더와 Todo 영역의 크기를 조정한다.

## 변경사항

기존과 반대로 **캘린더를 더 작게**, Todo 영역을 더 넓게 표시한다.

```text
변경 전

┌──────────────────────────┬────────────────────┐
│                          │                    │
│        Calendar          │        Todo        │
│                          │                    │
└──────────────────────────┴────────────────────┘


변경 후

┌───────────────────┬───────────────────────────┐
│                   │                           │
│     Calendar      │           Todo            │
│                   │                           │
└───────────────────┴───────────────────────────┘
```

### 기준

* 캘린더는 현재보다 compact하게 표시한다.
* Todo 영역은 캘린더보다 넓은 영역을 사용한다.
* 두 영역 사이에 기존에 정의한 명확한 경계선은 추가하지 않는다.
* 기존 반응형 동작은 유지한다.

# 3. 카테고리 삭제 확인

현재는 미완료 Todo가 남아 있는 카테고리도 삭제할 수 있도록 변경한다.

단, **미완료 Todo가 존재하는 경우 삭제 전 확인을 요청한다.**

## 동작

### 미완료 Todo가 없는 경우

카테고리를 바로 삭제할 수 있다.

```text
카테고리 삭제
    ↓
삭제
```

### 미완료 Todo가 있는 경우

삭제하기 전에 Confirm 창을 표시한다.

```text
카테고리 삭제
    ↓
미완료 Todo 존재
    ↓
Confirm
    ↓
사용자 확인
    ↓
삭제
```

### Confirm 내용

사용자가 해당 카테고리를 삭제해도 괜찮은지 명확하게 알 수 있어야 한다.

예시:

```text
이 카테고리에 미완료 할 일이 있습니다.
정말 삭제하시겠습니까?

[취소] [삭제]
```

### 중요

* 사용자가 `취소`를 선택하면 카테고리를 삭제하지 않는다.
* 사용자가 `삭제`를 선택한 경우에만 삭제한다.
* Confirm 없이 미완료 Todo가 자동으로 삭제되면 안 된다.
* 기존 카테고리 삭제 기능은 유지한다.

# 4. 캘린더 날짜별 카테고리 overflow 처리

특정 날짜에 카테고리가 많아질 경우 해당 주(week)의 높이만 비정상적으로 커지는 문제가 있다.

## 문제

```text
┌────┬────┬────┬────┬────┬────┬────┐
│    │    │    │    │    │    │    │
│    │    │ 많은│    │    │    │    │
│    │    │카테고리│   │    │    │    │
│    │    │    │    │    │    │    │
│    │    │    │    │    │    │    │
└────┴────┴────┴────┴────┴────┴────┘
             ↑
      특정 주만 지나치게 길어짐
```

## 요구사항

날짜에 카테고리가 많아지더라도 특정 주의 높이가 과도하게 증가하지 않도록 처리한다.

### 기본 원칙

* 캘린더의 각 주 높이가 콘텐츠 개수에 따라 무한정 증가하지 않도록 한다.
* 기존 날짜 및 카테고리 정보가 완전히 사라지지는 않도록 한다.
* 많은 카테고리가 있는 날짜에서도 UI가 깨지지 않아야 한다.
* Todo 영역의 사용성을 저해하지 않아야 한다.

### 구현 방향

카테고리가 표시 가능한 영역을 초과할 경우:

* 일정 개수까지만 기본적으로 표시하고
* 나머지 카테고리는 적절한 overflow 방식으로 처리한다.

예:

```text
┌──────────────┐
│ 업무       2 │
│ 공부       1 │
│ 운동       3 │
│ + 2개        │
└──────────────┘
```

단, 기존 UI 스타일과 자연스럽게 어울리는 방식으로 구현한다.

# 5. 상단 네비게이션에 홈 버튼 추가

현재 상단에 있는 `설정`, `프로필` 버튼에 **홈 버튼을 추가**한다.

## 변경 전

```text
[설정] [프로필]
```

## 변경 후

```text
[홈] [설정] [프로필]
```

### 요구사항

* 홈 버튼은 설정 버튼과 함께 상단에 고정한다.
* 프로필 버튼도 기존 위치와 동작을 유지한다.
* 홈 버튼을 클릭하면 홈 화면으로 이동한다.
* 기존 설정 / 프로필 기능에는 영향을 주지 않는다.

# 6. Todo 수정 기능

현재 Todo는 생성 후 수정할 수 없다.

Todo를 클릭하면 **수정 모드**로 전환할 수 있도록 변경한다.

## 수정 모드 진입

Todo의 다음 영역을 클릭하면 수정 모드로 전환한다.

```text
┌──────────────────────────────────────┐
│ □  할 일 내용                    🗑 │
└──────────────────────────────────────┘
```

### 클릭 영역

**체크박스와 삭제 버튼을 제외한 Todo 텍스트 영역**을 클릭했을 때만 수정 모드가 실행된다.

* 체크박스 클릭 → 기존 완료/미완료 동작
* 삭제 버튼 클릭 → 기존 삭제 동작
* Todo 텍스트 영역 클릭 → 수정 모드

즉, Todo 전체를 클릭하는 방식이 아니라 **텍스트 영역을 클릭하는 방식**으로 한다.

---

## 수정 모드

수정 모드에서는 기존 Todo의 텍스트를 편집할 수 있어야 한다.

```text
기존

□ 운동하기


수정 모드

□ [운동하기              ] 🗑
```

### 동작

1. Todo 텍스트 영역을 클릭한다.
2. 해당 Todo가 수정 상태로 변경된다.
3. 기존 Todo 내용이 Input에 표시된다.
4. 내용을 수정한다.
5. 수정 내용을 저장한다.
6. 수정된 내용이 Todo에 반영된다.

---

## 동시 수정 제한

**한 번에 하나의 Todo만 수정할 수 있다.**

예:

```text
Todo A → 수정 중

Todo B → 수정 모드 진입 불가
```

현재 Todo가 수정 중인 상태에서는 다른 Todo를 수정 모드로 변경하지 않는다.

### 중요

* 체크박스의 기존 동작을 변경하지 않는다.
* 삭제 버튼의 기존 동작을 변경하지 않는다.
* 수정 모드에서 Todo 데이터가 유실되지 않아야 한다.
* 저장하지 않은 상태에서 다른 Todo가 수정 모드로 변경되지 않도록 한다.

# 7. 습관 기능 추가

새로운 `습관` 영역을 추가한다.

기존 홈 / 설정 / 프로필 구조에 습관을 추가하여 상단 네비게이션에서 접근할 수 있도록 한다.

## 상단 네비게이션

```text
[홈] [습관] [설정] [프로필]
```

각 메뉴는 독립적인 화면으로 이동한다.

---

# 8. 습관 화면

## 목적

Todo와 별도로 **반복적으로 수행하는 행동을 습관/루틴으로 관리**할 수 있도록 한다.

Todo는 특정 날짜에 해야 하는 작업을 관리하고,

습관은 반복적으로 수행하고 싶은 루틴을 관리한다.

---

## 8-1. 습관 추가

사용자가 새로운 습관을 추가할 수 있어야 한다.

예:

```text
+ 습관 추가

┌─────────────────────────┐
│ 물 마시기                │
│ 매일                     │
└─────────────────────────┘

┌─────────────────────────┐
│ 운동                     │
│ 매주 월/수/금             │
└─────────────────────────┘
```

### 습관에 필요한 기본 정보

* 습관 이름
* 반복 주기

반복 주기는 우선 다음 범위를 지원한다.

* 매일
* 특정 요일 반복

예:

```text
매일
월 / 수 / 금
화 / 목
```

---

# 9. 습관 완료 여부 확인

습관은 해당 날짜에 **실행했는지 / 실행하지 않았는지** 확인할 수 있어야 한다.

예:

```text
오늘의 습관

☑ 물 마시기
☐ 운동
☑ 독서
```

### 동작

* 사용자가 체크하면 해당 날짜의 습관을 완료한 것으로 기록한다.
* 체크를 해제하면 해당 날짜의 완료 상태를 취소한다.
* 습관의 완료 여부는 날짜별로 관리한다.

예:

```text
10월 1일
☑ 물 마시기

10월 2일
☐ 물 마시기
```

동일한 습관이라도 날짜별 완료 상태는 서로 독립적이어야 한다.

---

# 10. 습관과 Todo 데이터 분리

습관은 Todo와 별도의 데이터로 관리한다.

### Todo

```text
특정 날짜에 해야 할 일
```

### 습관

```text
반복적으로 수행하는 루틴
+
날짜별 완료 여부
```

Todo의 완료 상태와 습관의 완료 상태를 서로 공유하거나 동일한 데이터로 처리하지 않는다.
